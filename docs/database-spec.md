## 1. 데이터 구성과 파일 위치

Python은 원본 Excel에서 제품 측정값과 검사 기준을 읽는다. 이 두 표를 SQLite DB에 저장한 다음 SQL로 다시 조회하여 Python 조건문으로 판정한다. 입력 데이터뿐 아니라 제품별 결과와 항목별 상세도 DB에 저장한다.

여기서 `DataFrame`은 Python 메모리 안의 표이고, DB 테이블은 `.db` 파일에 저장된 표이다.

| 데이터 | Python 변수 | DB 테이블 | 한 행의 의미 | 확인한 행 × 열 |
|---|---|---|---|---:|
| 측정 데이터 | `measurements` | `measurements` | 제품 하나의 정보와 13개 측정값 | 30 × 16 |
| 적용 기준 | `criteria` | `criteria` | 검사항목·적용소재 한 조합의 기준 | 15 × 6 |
| 제품별 결과 | `result` | `inspection_results` | 제품 하나의 최종 판정과 사유 | 30 × 18 |
| 항목별 상세 | `detail` | `inspection_details` | 제품 하나의 검사항목 하나에 대한 판정 | 390 × 7 |

행 수는 확인한 데이터의 개수이다. 제품 수를 30개로 제한하는 코드는 없다. 현재 검사항목은 13종이므로 상세 행 수는 `30 × 13 = 390`이다. 기준표는 공통 기준 12행과 소재별 굴절률 기준 3행으로 총 15행이다.

아래 경로는 프로젝트 폴더 `workspace/lens_quality`를 기준으로 적었다.

| 파일·폴더 | 기본 경로 | 역할 |
|---|---|---|
| 원본 Excel | `data/lens_qualityCheck.xlsx` | 프로그램에 입력하는 기준표·측정 데이터 |
| SQLite DB | `../../resources/lens_quality/outputs/results/lens_quality.db` | 입력 및 검사 결과의 4개 테이블 |
| 결과 Excel | `../../resources/lens_quality/outputs/results/lens_inspection_result.xlsx` | 검사결과·항목별상세·적용기준 시트 |
| SQL 내보내기 | DB와 같은 폴더의 `lens_quality.sql` | 별도 내보내기 실행 시 생성하는 구조와 현재 데이터 |
| HTML 조회 화면 | 기본 결과 폴더의 `조회화면` | `view_db.py`의 일반 조회 시 생성하는 HTML |
| 구조 명세 SQL | `docs/schema.sql` | 데이터 없이 4개 테이블 구조만 정의 |

현재 기본 결과 폴더의 절대 경로는 다음과 같다.

```text
C:\Hitech_subsidy\AI_automize\resources\lens_quality\outputs\results
```

`Lens.py`의 `BASE`는 해당 코드 파일이 있는 폴더이다. `RESULTS`는 `BASE.parents[1]` 아래의 `resources/lens_quality/outputs/results`로 계산한다. 터미널을 연 위치가 결과 경로를 결정하는 것은 아니다.

GUI에서는 원본 Excel과 결과 폴더를 따로 선택할 수 있다. 결과 폴더를 바꿔도 검사 결과의 기본 파일명은 `lens_quality.db`와 `lens_inspection_result.xlsx`이다. GUI의 경로 선택은 `Lens.py`, `view_db.py`, `export_sql.py`를 터미널에서 실행할 때의 기본 경로를 변경하지 않는다.

## 2. 원본 Excel 입력 명세

`Lens.load_excel_data()`가 `pd.read_excel()`로 읽는다. 두 시트 모두 1행을 컬럼명으로 사용한다.

| 시트 | 읽는 열·행 | 현재 실제 입력 범위 | 읽지 않는 데이터 |
|---|---|---|---|
| `측정데이터` | `usecols="A:P"`, 데이터 행 수 제한 없음 | 헤더 A1:P1, 제품 A2:P31 | Q열 이후의 기존 판정·사유·보조 계산 |
| `기준표` | `usecols="A:F", nrows=15` | 헤더 A1:F1, 기준 A2:F16 | G:H 설명, 17행 이후의 주석·집계 |

원본 `측정데이터`의 Q열 `판정`, R열 `판정사유`, S열 `기존판정`, T열 `기존불량사유`, U:AG 보조 판정 열은 검사 입력으로 사용하지 않는다. Python은 기존 판정을 복사하지 않고 A:P의 측정값과 기준표를 사용해 다시 판정한다.

확인한 원본 통합문서에는 수식이 452개 있지만 위의 실제 입력 범위에는 수식이 없다. 기존 판정 수식의 결과는 이 프로그램의 판단 근거가 아니다. 코드 자체에는 입력 셀에 수식이 있는지 검사하거나 Excel 수식을 재계산하는 기능이 없다.

### 2.1 측정 데이터 컬럼: `measurements`

아래 SQL 자료형은 현재 DB에서 확인한 선언이다. `TEXT`는 문자열, `INTEGER`는 정수, `REAL`은 실수용이다. 단위는 현재 기준표의 표기를 따른다.

| Excel 열 | 컬럼명 | SQL 자료형 | 단위 | 의미·예시 |
|---|---|---|---|---|
| A | `제품번호` | TEXT | — | 제품 식별값. 예: `L001` |
| B | `소재종류` | TEXT | — | `CR-39`, `하이인덱스`, `폴리카보네이트` |
| C | `제품명` | TEXT | — | 예: `루체나 스탠다드 016` |
| D | `스크래치등급` | INTEGER | Grade | 스크래치 정도를 나타내는 실습용 등급 |
| E | `기포이물질개수` | INTEGER | ea | 기포·이물질 개수 |
| F | `코팅불량개수` | INTEGER | ea | 코팅 불량 개수 |
| G | `굴절률` | REAL | n | 소재별 기준이 다른 굴절률 |
| H | `광투과율` | REAL | % | 빛을 통과시키는 비율 |
| I | `왜곡률` | REAL | % | 왜곡 정도 |
| J | `렌즈직경` | REAL | mm | 렌즈의 직경 |
| K | `중심두께` | REAL | mm | 렌즈 중심의 두께 |
| L | `가장자리두께` | REAL | mm | 렌즈 가장자리의 두께 |
| M | `곡률반경` | REAL | mm | 렌즈 곡면의 반경 |
| N | `UV차단율` | REAL | % | 자외선 차단 비율 |
| O | `색상균일도` | REAL | ΔE | 색 차이에 관한 실습용 측정값 |
| P | `틴트농도` | REAL | % | 착색 농도 |

제품번호는 현재 `L001`~`L030`이다. 프로그램이 제품번호를 새로 붙이거나 소재·제품명 순으로 재배치하지는 않는다. 검사할 때는 SQL의 `ORDER BY "제품번호"`로 제품을 정렬한다.

16개 컬럼은 모두 필요하다. 제품번호가 빈 행은 제외하고, 중복 제품번호는 입력 오류로 처리한다. 나머지 빈 값의 처리는 4절을 따른다. 위 세 소재는 현재 데이터에 등장하는 값이며 DB에 허용값 제약이 설정된 것은 아니다.

### 2.2 기준 컬럼: `criteria`

| Excel 열 | 컬럼명 | SQL 자료형 | 역할 |
|---|---|---|---|
| A | `검사항목` | TEXT | 측정 데이터의 검사 컬럼명과 연결. 예: `렌즈직경` |
| B | `적용소재` | TEXT | `공통` 또는 해당 제품의 `소재종류`와 같은 문자열 |
| C | `단위` | TEXT | mm, %, Grade, ea, n, ΔE 등의 설명 |
| D | `하한` | REAL | 합격으로 허용하는 최솟값 |
| E | `목표치` | REAL | 참고용 목표값. 합격·불합격 비교에는 사용하지 않음 |
| F | `상한` | REAL | 합격으로 허용하는 최댓값 |

`목표치`도 숫자 변환 검증 및 DB·결과 Excel 저장 대상이다. 다만 판정 조건은 `하한 ≤ 측정값 ≤ 상한`뿐이다. `단위`에 따른 값 변환이나 단위 일치 검사는 하지 않는다.

### 2.3 확인한 기준값 15행

| Excel 행 | 검사항목 | 적용소재 | 단위 | 하한 | 목표치 | 상한 |
|---:|---|---|---|---:|---:|---:|
| 2 | 스크래치등급 | 공통 | Grade | 0 | 0 | 2 |
| 3 | 기포이물질개수 | 공통 | ea | 0 | 0 | 1 |
| 4 | 코팅불량개수 | 공통 | ea | 0 | 0 | 1 |
| 5 | 광투과율 | 공통 | % | 85 | 92 | 100 |
| 6 | 왜곡률 | 공통 | % | 0 | 0 | 2 |
| 7 | 렌즈직경 | 공통 | mm | 70 | 72 | 74 |
| 8 | 중심두께 | 공통 | mm | 1.8 | 2 | 2.2 |
| 9 | 가장자리두께 | 공통 | mm | 1.3 | 1.5 | 2 |
| 10 | 곡률반경 | 공통 | mm | 74 | 80 | 88 |
| 11 | UV차단율 | 공통 | % | 99 | 100 | 100 |
| 12 | 색상균일도 | 공통 | ΔE | 0 | 0 | 1.5 |
| 13 | 틴트농도 | 공통 | % | 17 | 20 | 23 |
| 14 | 굴절률 | CR-39 | n | 1.495 | 1.5 | 1.505 |
| 15 | 굴절률 | 폴리카보네이트 | n | 1.58 | 1.586 | 1.6 |
| 16 | 굴절률 | 하이인덱스 | n | 1.66 | 1.68 | 1.7 |

경계값은 포함한다. 예를 들어 렌즈직경이 정확히 70 또는 74이면 해당 항목은 합격이다. 반올림 후 비교하거나 별도의 오차 허용값을 더하는 처리는 없다.

입력 숫자는 pandas의 숫자 변환과 SQL 저장·조회를 거친다. 따라서 Excel 셀 서식이나 `1.00` 같은 표시 형식까지 복사하는 것은 아니다.

### 3.2 항목별 상세: `inspection_details`

| 순서 | 컬럼명 | SQL 자료형 | 값의 출처·의미 |
|---:|---|---|---|
| 1 | `제품번호` | TEXT | 현재 검사 중인 제품의 식별값 |
| 2 | `검사항목` | TEXT | 현재 반복 중인 검사 항목 |
| 3 | `측정값` | REAL | 해당 제품의 해당 항목 값 |
| 4 | `하한` | REAL | 실제 선택한 기준의 하한. 기준 선택 실패 시 NULL |
| 5 | `상한` | REAL | 실제 선택한 기준의 상한. 기준 선택 실패 시 NULL |
| 6 | `항목판정` | TEXT | `합격`, `불합격`, `판정불가` |
| 7 | `사유` | TEXT | 해당 항목의 합격 범위 또는 오류·불합격 설명 |

예시: `L002`의 `렌즈직경`은 측정값 `69.61`, 하한 `70`, 상한 `74`이며, 항목판정은 `불합격`, 사유는 `렌즈직경: 69.61 < 하한 70`이다.

상세에는 소재명이나 제품명이 별도로 없다. 필요하면 `제품번호`로 `measurements`와 연결해서 조회한다.

## 4. 입력 검증과 누락 처리

입력 검증은 `load_excel_data()`에서 수행하며, 이 단계가 실패하면 `run_inspection()`은 새 결과 폴더 생성 및 DB 저장 단계로 진행하지 않는다.

### 4.1 입력 단계의 검증과 처리

| 조건 | 현재 처리 |
|---|---|
| 원본 파일 없음, 시트를 읽을 수 없음 | 예외로 중단 |
| 측정 데이터 16개 필수 컬럼 또는 기준표 6개 컬럼 누락 | `ValueError`로 중단 |
| 제품번호가 빈 행 | 해당 행을 제외 |
| 위 행을 제외한 뒤 제품이 하나도 없음 | `ValueError`로 중단 |
| 제품번호 중복 | `ValueError`로 중단 |
| `검사항목 + 적용소재` 조합 중복 | `ValueError`로 중단 |
| 기준표의 검사항목 이름이 빈 행 | `ValueError`로 중단 |
| 13개 필수 검사항목 중 하나가 기준표 전체에서 빠짐 | `ValueError`로 중단 |
| 기준표의 항목에 대응하는 측정 데이터 컬럼 없음 | `ValueError`로 중단 |
| 측정값 또는 하한·목표치·상한을 숫자로 변환할 수 없음 | `ValueError`로 중단. 0으로 바꾸지 않음 |

`REQUIRED_ITEMS`에 13개 필수 항목이 별도로 정의되어 있다. 따라서 기준표에서 검사 항목 자체를 지워 해당 검사를 조용히 생략하게 만드는 방식으로 동작하지 않는다.

### 4.2 검사는 계속하되 항목을 판정불가로 기록하는 경우

| 조건 | 항목판정 | 사유 |
|---|---|---|
| 적용되는 기준이 0개 또는 2개 이상 | 판정불가 | `{항목}: 적용 기준 누락 또는 중복` |
| 적용 기준은 하나지만 측정값이 결측값 | 판정불가 | `{항목}: 측정값 누락` |
| 하한 또는 상한이 결측값 | 판정불가 | `{항목}: 기준 누락` |
| 하한이 상한보다 큼 | 판정불가 | `{항목}: 하한이 상한보다 큼` |

항목 전체가 기준표에서 빠지는 경우와, 예를 들어 굴절률 항목은 있지만 특정 소재의 기준만 빠지는 경우는 다르다. 전자는 입력 검증에서 중단하고, 후자는 해당 소재 제품의 굴절률을 판정불가로 기록한다.

빈 숫자 셀 등 pandas가 결측값으로 읽는 값은 숫자가 아닌 일반 문자열과 다르게 처리된다. 목표치가 결측값이어도 목표치를 판정에 쓰지 않으므로 그것만으로 판정불가가 되지는 않는다.

### 4.3 현재 구현에서 검사하지 않는 형식

- 제품번호의 `L001` 형식, 연속 번호, 공백만 있는 제품번호
- 소재종류·제품명·단위의 필수값 여부와 허용값 목록
- 문자열 앞뒤 공백 제거, 대소문자 또는 표기 통일
- 개수·등급 항목이 정수인지, 측정값이 유한한 숫자인지
- 측정 단위의 자동 환산 및 목표치가 하한·상한 사이인지

따라서 입력 이름과 소재 문자열은 원본의 정확한 표기를 유지해야 한다. DB 자료형이 INTEGER라고 선언되어 있다는 것만으로 애플리케이션에서 정수 여부를 검증하는 것은 아니다.

## 5. 판정 규칙

### 5.1 제품·항목에 맞는 기준 선택

`run_inspection()`은 제품 하나를 꺼낸 뒤 기준표의 서로 다른 검사항목을 순회한다. 각 항목의 기준은 다음 조건으로 찾는다.

```text
기준.검사항목 = 현재 검사항목
그리고
(기준.적용소재 = "공통" 또는 기준.적용소재 = 제품.소재종류)
```

이 조건에 맞는 행이 정확히 1개일 때 `matched.iloc[0]`으로 그 행을 선택한다. `iloc[0]`은 원본 기준표의 첫 행을 계속 사용한다는 뜻이 아니라, 이번 항목·소재로 필터링한 표의 첫 번째 행을 뜻한다.

공통 기준과 소재별 기준이 동시에 있으면 소재별 기준을 우선하지 않는다. 두 행이 선택되므로 판정불가이다. 동일 항목·소재의 완전 중복은 그보다 앞선 입력 검증에서 중단한다.

### 5.2 항목별 숫자 비교

적용 기준이 하나이면 `check_value()`를 호출한다. 다음 순서대로 처음 해당하는 결과를 반환한다.

| 순서 | 조건 | 반환 판정 |
|---:|---|---|
| 1 | 측정값 결측 | 판정불가 |
| 2 | 하한 또는 상한 결측 | 판정불가 |
| 3 | 하한 > 상한 | 판정불가 |
| 4 | 측정값 < 하한 | 불합격 |
| 5 | 측정값 > 상한 | 불합격 |
| 6 | 나머지 경우 | 합격 |

기준 선택이 먼저이므로, 적용 기준도 없고 측정값도 없으면 `적용 기준 누락 또는 중복` 사유가 기록된다. 사유 문자열의 `:g`는 숫자 표시 형식을 정할 뿐 비교할 값을 반올림하지 않는다.

### 5.3 제품 최종 판정과 사유

| 제품의 항목별 결과 | 최종 `판정` |
|---|---|
| 불합격이 하나라도 있음 | 불합격 |
| 불합격은 없고 판정불가가 있음 | 판정불가 |
| 모든 항목이 합격 | 합격 |

불합격과 판정불가가 함께 있으면 제품은 불합격이다. `판정사유`에는 불합격 사유들을 먼저, 판정불가 사유들을 그다음에 줄바꿈(`\n`)으로 붙인다. 모든 항목이 합격이면 현재 기준으로 `13개 항목 모두 허용범위 이내`가 들어간다.

## 6. DB 관계·저장 방식·제약조건

### 6.1 관계는 코드로 연결하며 DB가 강제하지 않음

| 관계 | 연결 기준 | 정상 검사 결과에서의 의미 |
|---|---|---|
| `measurements` ↔ `inspection_results` | 제품번호 | 제품 하나당 최종 결과 하나 |
| `measurements` ↔ `inspection_details` | 제품번호 | 제품 하나당 현재 13개 상세 결과 |
| `criteria` ↔ 상세 판정 | 검사항목 및 제품의 소재종류 | Python이 공통 또는 소재 기준을 선택 |

상세 행을 논리적으로 식별하는 조합은 `제품번호 + 검사항목`이다. 기준 행의 논리적 식별 조합은 `검사항목 + 적용소재`이다. 이 조합에 DB 기본키나 UNIQUE 제약을 설정한 것은 아니다.

실제 4개 테이블 모두 다음 제약조건이 없다.

- `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`
- `NOT NULL`, `CHECK`, 명시적 `DEFAULT`
- 별도로 만든 인덱스

따라서 모든 컬럼은 DB 구조상 NULL을 허용한다. 일부 오류를 Python에서 검사하는 것과 DB가 저장을 거부하는 것은 구분해야 한다. `to_sql(index=False)`는 pandas 행 인덱스를 별도 컬럼으로 저장하지 않는다는 뜻이다. 제품번호를 기본키로 지정하는 옵션이 아니다.

`schema.sql`은 확인한 `sqlite_master`의 CREATE TABLE 정의를 담은 문서이다. 빈 SQLite DB에서 실행하면 데이터 없는 4개 테이블을 만든다. `Lens.py`는 이 파일을 읽거나 실행하지 않는다.

### 6.2 다시 검사하면 최신 내용으로 교체

4개 DataFrame은 `to_sql(..., if_exists="replace", index=False)`로 저장한다. 같은 이름의 테이블을 교체하므로 이전 검사 결과가 누적되지 않는다. 검사 실행 ID, 실행 시각, 기준 버전, 변경 이력을 저장하는 컬럼도 없다.

SQL 조회 결과의 행 순서는 `ORDER BY`가 없으면 보장되지 않는다. 검사에서는 제품번호를 정렬하며, 기준 읽기 SQL에는 별도 정렬 구문이 없다. 특정 표시 순서가 필요하면 조회 SQL에 `ORDER BY`를 지정해야 한다.

`dtype`를 고정하지 않아 테이블의 자료형은 pandas가 데이터에서 추론한다. 위 명세와 `schema.sql`은 확인일의 실제 구조이며, 입력 값이나 결측 상태가 바뀌면 재생성된 자료형이 달라질 수 있다.

### 6.3 오류 시 저장 상태

| 오류 시점 | 확인해야 할 상태 |
|---|---|
| 입력 검증 실패 | 이번 실행은 DB 쓰기 단계에 도달하지 않음 |
| DB 저장 도중 오류 | 일부 테이블만 갱신되었을 수 있음 |
| DB 저장 완료 후 Excel 저장의 파일 잠금·권한 등 OSError | DB에는 새 결과가 있고 Excel 저장만 실패할 수 있음 |
| SQL 내보내기 실패 | 검사 DB는 읽기 전용으로 사용. 완성한 임시 SQL 파일만 최종 경로로 교체 |

4개 테이블 전체와 Excel을 한 번에 성공하거나 모두 되돌리는 구조가 아니다. SQLite 연결을 `with conn`으로 감쌌더라도 pandas의 SQLite `to_sql()` 내부에서도 커밋하므로, 네 테이블 갱신 전체를 하나의 원자적 작업으로 보장하지 않는다.

Excel은 같은 저장 폴더 안에 임시 파일을 완성한 뒤 최종 파일로 교체한다. 저장 중 오류가 나면 기존 결과 Excel이 남을 수 있으므로, 파일이 존재한다는 사실만으로 이번 검사 결과라고 판단하면 안 된다.

## 7. Excel·GUI·HTML·SQL 출력

### 7.1 결과 Excel

| 시트 | 원본 DataFrame / 대응 DB 테이블 | 현재 데이터 범위 |
|---|---|---|
| `검사결과` | `result` / `inspection_results` | A1:R31 (헤더 포함) |
| `항목별상세` | `detail` / `inspection_details` | A1:G391 (헤더 포함) |
| `적용기준` | `criteria` / `criteria` | A1:F16 (헤더 포함) |

`save_result_excel()`은 `InspectionReport`에 담긴 표를 저장한다. 이 함수가 DB를 다시 읽거나 검사를 다시 실행하는 것은 아니다. `measurements`만의 별도 시트는 없으며 측정값은 검사결과의 첫 16개 컬럼에 들어 있다.

| 표시 대상 | 색상 |
|---|---|
| `판정` 또는 `항목판정`이 합격인 셀 | 연두 `#D9EAD3` |
| `판정` 또는 `항목판정`이 불합격인 셀 | 분홍 `#F4CCCC` |
| 불합격 원인이 된 검사결과의 측정값 셀 | 회색 `#D9D9D9` |
| 항목별상세에서 불합격인 행의 측정값 셀 | 회색 `#D9D9D9` |
| 판정불가 | 별도의 판정 색상 규칙 없음 |

색상은 Excel/GUI에서 표시하는 서식이다. DB에는 색상 컬럼이나 Excel 수식을 저장하지 않는다.

### 7.2 GUI에서 보는 데이터

- **검사 실행**: 선택한 원본 Excel을 읽어 판정하고 선택한 결과 폴더에 저장한다.
- **저장된 DB 열기**: 선택한 DB를 읽기 전용으로 조회한다. 새 검사나 Excel 저장을 시작하지 않는다.
- GUI 표는 읽어온 시점의 데이터이다. 검색·필터·정렬은 화면 표시를 바꾸며 DB의 값을 수정하지 않는다.
- 검사결과 화면은 제품번호·판정·소재종류·제품명·판정사유를 앞에 배치한다. DB와 결과 Excel의 컬럼 순서는 3절과 같다.
- SQL 미리보기는 DB를 읽은 시점의 내용이다. **SQL 내보내기**는 선택된 DB 경로를 다시 읽으므로 그 사이 다른 프로그램이 DB를 변경했다면 미리보기와 달라질 수 있다.
- Excel 재저장은 이 GUI 창에서 실행한 검사의 `InspectionReport`가 있을 때 가능하다. 저장된 DB만 열었다면 이 재저장 기능의 대상 보고서가 없다.

`InspectionReport`는 네 DataFrame, 판정 개수, 파일 경로, `excel_saved`와 `excel_error`를 담은 Python 객체이다. 다섯 번째 DB 테이블이 아니다. Excel의 OSError가 발생하면 `run_inspection()`은 `excel_saved=False`인 보고서를 반환한다. GUI는 저장을 재시도할 수 있고, 터미널 `Lens.py`는 오류를 안내하고 종료 코드 1로 끝난다. 그 밖의 예외는 호출한 곳으로 전달한다.

### 7.3 HTML과 SQL

| 구분 | 생성·조회 방법 | 포함 내용 |
|---|---|---|
| HTML 조회 화면 | `view_db.py 결과` 등 일반 조회 | 조회 시점의 표. 브라우저에서 확인 |
| SQL 문장 확인 | `view_db.py create`, `insert`, `sql` | 터미널에 구조·INSERT 문장 출력. SQL을 실행하는 기능이 아님 |
| 전체 SQL 내보내기 | `export_sql.py` 또는 GUI SQL 내보내기 | 현재 DB 전체의 구조와 INSERT 문장 |
| 구조 문서 | `docs/schema.sql` | 확인한 4개 테이블의 CREATE TABLE만 포함 |

`Lens.py` 검사만으로 HTML이나 `.sql` 파일이 생성되지는 않는다. HTML은 자동 갱신되지 않으므로 DB 변경 후 다시 조회해야 한다. HTML에는 판정 색상이 적용되지만 Excel·GUI의 불합격 원인 셀 회색 표시와 같은 범위의 서식을 제공하지는 않는다.

`export_sql()`은 SQLite의 `iterdump()`를 사용한다. SQL 내보내기는 입력 테이블과 결과 테이블을 모두 포함하며, 과거에 실행했던 SQL 명령의 이력이나 Python 판정 알고리즘을 내보내는 것은 아니다. DB에 추가 테이블이 있다면 그 테이블도 내보내기 대상이다.

### 8.1 재확인 방법과 결과

- 원본의 측정 데이터 30행·기준 15행이 DB 입력 테이블과 일치한다.

- DB는 4개 테이블·총 47개 컬럼이다. `PRAGMA quick_check` 결과는 `ok`이다.

| 기준 행 추가 | `nrows=15` 제한 및 공통·소재별 기준이 겹치지 않는지 |
| 판정 규칙 변경 | `check_value()`, 기준 선택, 제품 최종 판정, 기대 결과 |
| DB 구조 변경 | 실제 재생성 DB, `docs/schema.sql`, GUI·조회 코드가 기대하는 컬럼 |
| 판정 값·색상 변경 | Excel 서식, `table_model.py`, HTML 표시, 집계·필터 |

현재 명세는 실습용 단일 검사 결과를 저장하는 구현을 설명한다. 검사 이력, DB 제약조건, 기준 버전 관리, 모든 결과를 함께 저장하거나 취소하는 처리는 구현되어 있지 않다. 향후 이를 추가하면 실제 코드와 함께 이 문서도 갱신한다.
