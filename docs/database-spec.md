## 1. 저장 위치와 생성 방식

프로젝트 루트는 `Lens.py`가 있는 `lens_quality` 폴더입니다. 아래 경로는 모두 프로젝트 루트 기준입니다.

| 구분 | 경로 / 생성 주체 |
|---|---|
| 입력 Excel | `data/lens_qualityCheck.xlsx` |
| SQLite DB | `../../resources/lens_quality/outputs/results/lens_quality.db` |
| DB 생성·갱신 | `Lens.py`의 `sqlite3.connect(DB_FILE)` 및 `DataFrame.to_sql()` |
| 전체 SQL 내보내기 | `export_sql.py` 실행 시 DB와 같은 폴더의 `lens_quality.sql` |
| 구조 명세용 SQL | 이 문서와 같은 폴더의 `schema.sql` |

`schema.sql`은 실제 DB의 구조를 설명하고 빈 DB에 같은 테이블을 만드는 파일입니다. `Lens.py`가 이 파일을 읽어서 실행하는 것은 아닙니다. `export_sql.py`의 출력은 네 테이블의 구조와 현재 데이터에 대한 `INSERT`를 포함하므로 구조 명세용 파일과 구분합니다.

현재 출력 경로는 `BASE.parents[1]`에 의존합니다. 프로젝트만 다른 위치에 복사하면 결과가 프로젝트의 두 단계 상위 폴더 아래에 만들어집니다. 프로젝트 내부 `results`로 변경하는 것은 향후 개선 사항입니다.

## 2. 테이블 개요

| 테이블 | 한 행의 의미 | 데이터 출처 | 확인한 행 수 | 컬럼 수 |
|---|---|---|---:|---:|
| `measurements` | 제품 하나의 정보와 13개 측정값 | 입력 Excel의 `측정데이터` 시트 A:P | 30 | 16 |
| `criteria` | 검사 항목·적용소재 조합 하나의 기준 | 입력 Excel의 `기준표` 시트 A:F, 제목 다음 최대 15행 | 15 | 6 |
| `inspection_results` | 제품 하나의 측정값과 최종 판정 | Python의 `summaries` → `result` | 30 | 18 |
| `inspection_details` | 제품 하나의 검사 항목 하나에 대한 판정 | Python의 `details` → `detail` | 390 | 7 |

행 수는 확인 당시 저장된 데이터의 예시이며 테이블 용량 제한이 아닙니다. 정상 처리 시 제품별 검사 항목 수는 `criteria`의 서로 다른 `검사항목` 개수에 따릅니다. 현재는 13개이므로 상세 결과는 30 × 13 = 390행입니다. 기준표 입력에는 `nrows=15` 제한이 있습니다.

## 3. 실제 DB 제약조건과 논리적 관계

현재 네 테이블에는 다음 제약조건이 **선언되어 있지 않습니다.**

- 기본키(`PRIMARY KEY`), 외래키(`FOREIGN KEY`), 고유 제약조건(`UNIQUE`)
- `NOT NULL`, `CHECK`, 기본값(`DEFAULT`)
- 명시적으로 생성한 인덱스

따라서 **모든 컬럼은 DB 수준에서 NULL을 허용**합니다. 아래 컬럼 설명의 필수성이나 식별자 역할은 DB 제약조건과 구분해야 합니다. `to_sql(index=False)`는 pandas의 행 인덱스를 저장하지 않는다는 뜻이며 제품번호를 기본키로 지정하지 않습니다. SQLite의 내부 `rowid`는 업무용 제품번호가 아닙니다.

| 연결 | 논리적인 관계 | 연결 방법 / 주의점 |
|---|---|---|
| `measurements` → `inspection_results` | 정상 실행 시 제품당 결과 1개 | `제품번호`가 동일. DB가 1:1 관계를 강제하지 않음 |
| `measurements` → `inspection_details` | 제품당 여러 검사 항목 결과 | `제품번호`가 동일. 논리적 식별 조합은 `제품번호 + 검사항목` |
| `criteria` → 항목 판정 | 항목과 제품 소재에 맞는 기준 1개 | 아래 기준 선택 조건을 Python에서 적용. 외래키 연결이 아님 |

기준 선택 조건:

```text
기준의 검사항목 = 현재 검사 항목
그리고
(기준의 적용소재 = '공통' 또는 기준의 적용소재 = 제품의 소재종류)
```

`inspection_details`에는 `소재종류`가 없으므로 소재를 확인하려면 제품번호로 `measurements` 등과 연결해야 합니다. 공통 기준과 해당 소재 기준이 동시에 선택되면 자동으로 소재 기준을 우선하지 않고 `판정불가`로 처리합니다.

## 4. 컬럼 명세

자료형은 현재 DB에서 확인한 선언형입니다. `TEXT`는 문자열, `INTEGER`는 정수, `REAL`은 실수용 선언형입니다. SQLite의 자료형 선언만으로 모든 입력 형식이 엄격히 검증되는 것은 아닙니다. 현재 코드는 `to_sql()`의 `dtype`를 지정하지 않으므로 재생성할 때 데이터에 따라 선언형이 달라질 수 있습니다.

단위는 저장된 `criteria.단위`를 기준으로 적었습니다. 측정 장비·방법·등급 정의는 별도로 확인된 명세가 없으며, 단위 자동 변환 기능은 없습니다.

### 4.1 measurements — 입력 측정 데이터

제품번호가 비어 있는 행을 제외한 뒤 저장합니다. Excel의 기존 판정·판정사유 열은 입력 범위에 포함하지 않습니다. 아래 예시는 저장된 L001 제품에서 가져왔습니다.

| 순서 | 컬럼명 | DB 자료형 | 의미 | 단위 | 예시 |
|---:|---|---|---|---|---|
| 1 | 제품번호 | TEXT | 제품 식별에 사용하는 값 | 없음 | L001 |
| 2 | 소재종류 | TEXT | 소재별 기준을 선택할 때 사용하는 렌즈 소재 | 없음 | CR-39 |
| 3 | 제품명 | TEXT | 제품 이름 | 없음 | 루체나 스탠다드 016 |
| 4 | 스크래치등급 | INTEGER | 표면 스크래치 등급 측정값 | Grade | 1 |
| 5 | 기포이물질개수 | INTEGER | 기포·이물질 개수 측정값 | ea | 0 |
| 6 | 코팅불량개수 | INTEGER | 코팅 불량 개수 측정값 | ea | 1 |
| 7 | 굴절률 | REAL | 소재별로 검사하는 굴절률 | n (무차원, 원본 표기) | 1.504 |
| 8 | 광투과율 | REAL | 빛의 투과율 측정값 | % | 90.5 |
| 9 | 왜곡률 | REAL | 왜곡률 측정값 | % | 1.0 |
| 10 | 렌즈직경 | REAL | 렌즈 지름 측정값 | mm | 72.22 |
| 11 | 중심두께 | REAL | 렌즈 중심 두께 측정값 | mm | 2.03 |
| 12 | 가장자리두께 | REAL | 렌즈 가장자리 두께 측정값 | mm | 1.51 |
| 13 | 곡률반경 | REAL | 렌즈 곡률반경 측정값 | mm | 84.1 |
| 14 | UV차단율 | REAL | 자외선 차단율 측정값 | % | 99.2 |
| 15 | 색상균일도 | REAL | 색상균일도 검사에 사용하는 측정값 | ΔE | 0.93 |
| 16 | 틴트농도 | REAL | 틴트 농도 측정값 | % | 17.7 |

현재 소재값은 `CR-39`, `하이인덱스`, `폴리카보네이트`입니다. 이를 강제하는 DB 제약조건이나 별도 허용값 검사는 없습니다. 제품번호의 `L001` 형식과 길이도 코드가 강제하지 않습니다.

### 4.2 criteria — 검사 기준

논리적 식별 조합은 `검사항목 + 적용소재`입니다. 같은 조합의 중복은 Python에서 검사합니다.

| 순서 | 컬럼명 | DB 자료형 | 의미 | 단위 / 예시 |
|---:|---|---|---|---|
| 1 | 검사항목 | TEXT | `measurements`의 측정 컬럼과 연결할 이름 | 렌즈직경 |
| 2 | 적용소재 | TEXT | 공통 또는 특정 소재 | 공통 |
| 3 | 단위 | TEXT | 해당 항목의 단위 표기 | mm |
| 4 | 하한 | REAL | 허용 최솟값. 해당 값 자체도 합격 범위에 포함 | 해당 항목 단위 / 70.0 |
| 5 | 목표치 | REAL | 저장·표시용 목표값. 현재 판정에는 사용하지 않음 | 해당 항목 단위 / 72.0 |
| 6 | 상한 | REAL | 허용 최댓값. 해당 값 자체도 합격 범위에 포함 | 해당 항목 단위 / 74.0 |

### 4.4 inspection_details — 항목별 검사 결과

합격·불합격·판정불가를 모두 저장합니다. 논리적 식별 조합은 `제품번호 + 검사항목`이며 DB 고유 제약조건은 없습니다.

| 순서 | 컬럼명 | DB 자료형 | 의미 | 예시 |
|---:|---|---|---|---|
| 1 | 제품번호 | TEXT | 검사한 제품의 번호 | L001 |
| 2 | 검사항목 | TEXT | 이번에 검사한 항목 이름 | 스크래치등급 |
| 3 | 측정값 | REAL | 해당 제품·항목의 값. 누락 시 NULL 가능 | 1.0 |
| 4 | 하한 | REAL | 적용한 기준의 하한. 기준을 하나로 선택하지 못하면 NULL | 0.0 |
| 5 | 상한 | REAL | 적용한 기준의 상한. 기준을 하나로 선택하지 못하면 NULL | 2.0 |
| 6 | 항목판정 | TEXT | 합격 / 불합격 / 판정불가 | 합격 |
| 7 | 사유 | TEXT | 항목별 판정 근거 | 스크래치등급: 허용범위 0~2 이내 |

`측정값`, `하한`, `상한`의 단위는 `검사항목`에 따라 다릅니다. 개수 항목도 여러 항목을 합친 이 테이블에서는 현재 `REAL`로 저장되어 있습니다.

## 6. 판정 및 입력 검증

### 항목별 판정 순서

기준 선택 결과가 정확히 한 행이 아니면 먼저 `판정불가`로 처리합니다. 한 행이면 `check_value()`가 다음 순서로 검사합니다.

| 순서 | 조건 | 항목판정 / 사유 |
|---:|---|---|
| 1 | 측정값이 누락됨 | 판정불가 / 측정값 누락 |
| 2 | 하한 또는 상한이 누락됨 | 판정불가 / 기준 누락 |
| 3 | 하한 > 상한 | 판정불가 / 하한이 상한보다 큼 |
| 4 | 측정값 < 하한 | 불합격 / 측정값과 하한 표시 |
| 5 | 측정값 > 상한 | 불합격 / 측정값과 상한 표시 |
| 6 | 위 조건에 해당하지 않음 | 합격 / 허용범위 표시 |

제품 최종 판정은 `불합격 항목 있음 → 불합격`, `불합격 없이 판정불가 항목 있음 → 판정불가`, `모두 합격 → 합격` 순서입니다. 두 종류의 문제가 함께 있으면 최종 판정은 불합격이지만 두 종류의 사유를 모두 저장합니다.

### 판정불가와 구분해야 하는 입력 처리

| 입력 상황 | 현재 코드의 동작 |
|---|---|
| 제품번호가 비어 있음 | 해당 행을 제거하고 진행 |
| 제품번호 중복 | `ValueError`로 중단 |
| 같은 검사항목·적용소재 조합 중복 | `ValueError`로 중단 |
| 숫자로 바꿀 수 없는 측정값 또는 하한·목표치·상한 | `pd.to_numeric(errors="raise")`에서 오류로 중단 |
| 필요한 컬럼 이름이 없음 | 해당 컬럼 접근 시 오류로 중단. 판정불가 결과를 자동 생성하지 않음 |
| 항목은 기준표에 있으나 해당 제품에 맞는 기준이 없음 | 해당 항목 판정불가 |
| 공통 기준과 해당 소재 기준이 모두 선택됨 | 해당 항목 판정불가 |
| 검사 항목 자체가 기준표에서 완전히 제거됨 | `items`가 기준표에서 만들어지므로 해당 항목이 검사에서 빠질 수 있음 |
| 기준표의 데이터가 15행을 초과함 | 16번째 데이터 행부터는 읽지 않음 |

개수·등급의 정수 여부, 허용 소재 목록, 측정 단위 일치 여부를 별도 검사하는 코드는 없습니다. 미래의 요구사항을 현재 구현된 검증으로 표기하지 않습니다.

## 7. 저장·조회·갱신 규칙

- 네 테이블은 각각 `to_sql(if_exists="replace", index=False)`로 교체됩니다. 과거 검사 이력을 누적하지 않습니다.
- 실행 ID, 검사 시각, 기준 버전 컬럼이 없어 실행 회차별 추적은 지원하지 않습니다.
- DB 저장 후 Excel 저장이 진행됩니다. Excel 파일 잠금 등으로 저장이 실패하면 DB는 갱신되었지만 Excel은 이전 상태일 수 있습니다. DB와 Excel을 묶은 원자적 저장 기능은 없습니다.
- `view_db.py`는 읽기 전용 DB 연결로 조회합니다. 기본 모드에서는 `조회화면/<명령>.html`을 생성하고 같은 명령을 다시 실행하면 덮어씁니다. HTML은 실시간 DB 화면이 아니므로 DB 갱신 뒤 조회 명령도 다시 실행해야 합니다.
- `export_sql.py`는 읽기 전용 DB 연결로 네 테이블의 구조와 현재 데이터를 내보냅니다. SQL 파일은 과거 실행 기록이나 Python 판정 로직을 포함하지 않습니다.
- `schema.sql`은 이 명세 작성 시점의 구조입니다. DB 컬럼이나 자료형을 변경하면 명세와 함께 갱신해야 합니다.

현재 구조를 확인하는 명령(프로젝트 폴더의 PowerShell에서 실행):

```powershell
.\.venv\Scripts\python.exe .\view_db.py 구조 --터미널
.\.venv\Scripts\python.exe .\view_db.py create
```

SQL 클라이언트에서는 아래와 같이 확인할 수 있습니다. 이 SQL 문장을 PowerShell에 그대로 입력하는 것은 아닙니다.

```sql
PRAGMA table_info("measurements");
PRAGMA foreign_key_list("inspection_details");
SELECT name, sql FROM sqlite_master WHERE type = 'table' ORDER BY name;
```

## 9. 향후 개선 사항 — 현재 미구현

1. 검사 항목 목록을 별도로 정의하여 기준표에서 항목 전체가 빠진 경우도 감지합니다.
2. 15행 고정 읽기를 개선하고 소재·단위·개수의 형식 검증을 추가합니다.
3. 기본키·외래키 등 필요한 DB 제약조건을 설계하고 `replace` 방식과 함께 검토합니다.
4. 검사 실행 ID·시각·기준 버전을 저장하여 이력을 보존합니다.
5. 프로젝트 내부 또는 사용자가 지정한 위치에 결과를 저장하도록 경로 설정을 개선합니다.
